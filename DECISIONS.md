# Decisions and deviations from SPEC.md

Dated log. Oldest first; a later entry supersedes what it contradicts.

## 2026-09-04 · M1 parser CLI

- **Chunking is the normal path, not the exception.** The on-device model reports `contextSize == 4096`. Instructions (~400 tokens) plus the extraction schema (~1100) leave ~1300 tokens per chunk, so a typical syllabus is 1–4 chunks. One fresh session per chunk (no shared transcript; it would not fit). Private Cloud Compute (32k context) is opt-in via `--pcc` / `.privateCloudCompute`, or the fallback when the on-device model is unavailable; the spec's "one pass if it fits" happens automatically on that route.
- **One schema per chunk instead of separate course/obligation passes.** Halves the call count. Cross-chunk state is a tiny `RollingContext` (course line, term line, known component names with platforms), not a rolling summary.
- **Deterministic guards around the model.** `dateAsWritten` must appear in the document text or the resolved date must be mentioned in it; otherwise the item is dropped and counted in `warnings`. Grade-table rows that reappear as dateless "obligations" are dropped. Component weights are ignored once the running total reaches 100%. `DateResolver` cross-checks the model's ISO date against the copied wording and the wording wins (flag `dateDisagreement`). This is what keeps false positives near zero on a 3B model.
- **Within-document conflicts are not flagged.** Identical titles with different dates inside one document are a series ("Quiz" on 9/10 and 9/17), not a conflict. The spec's conflict case (syllabus vs. later announcement) is cross-document and belongs to HorizonCore's re-ingest matching (M2).
- **Evaluations framework, synthetic fixtures.** `Tests/IngestEvals` uses the `Evaluations` framework (Swift Testing trait + `Evaluation` protocol). No real syllabi were available, so `Evals/Fixtures` holds 15 synthetic ones across departments and formats (text PDF, scanned PDF, docx, txt, PNG screenshots, a multi-chunk PDF, week-relative dates). Replace or extend with real documents; keep `expected.json` in the same shape. Evals run only with `HORIZON_EVALS=1`.
- **docx is macOS-only** (AppKit's `NSAttributedString` reader). On iOS a docx would need QuickLook rasterization; deferred until the share extension (M2).
- **No third-party dependencies.** CLI argument parsing is hand-rolled; ArgumentParser would be the only dependency and is not worth it for five flags.
- **`fm` CLI not used.** It requires `sudo fm license` acceptance, which is the user's call. The Swift API is used directly.
- **`.claude/skills/HIGAgentSkills/` is git-ignored.** It is a nested git checkout (embedded repository); committing it would add a broken submodule.
- **Platform enum** keeps the spec's five cases; `.syllabusOnly` doubles as "platform not stated". Obligations inherit the platform of their grade component when the document states it only there ("Homework (WebAssign)").
- **No `DynamicProfile` in M1.** The spec's §4.3 three-branch profile (ingest / askMyDocuments / plan) shares a transcript across modes. M1 has one mode and a 4096-token context, so it uses a fresh `LanguageModelSession(model:tools:instructions:)` per chunk. The profile arrives with the planner (M5), where mode switching actually happens.
- **Image pages get Vision OCR text as well as the model's own look.** Screenshots and scanned pages are sent to the model as image attachments (with `OCRTool` available), and `DocumentNormalizer` also runs `VNRecognizeTextRequest` so the source-text guards apply to them. Because OCR can misread a date, an unsupported date from an image page is kept as `.needsReview` instead of being dropped.
- **Year for undated dates comes from the term label, else `--year`, else today.** The data detector guesses a year relative to today (and ignores a trailing year once a time is present), so the detector's year is always replaced. A Fall syllabus mentioning a January date gets the term year, which is wrong by one; term-spanning inference is deferred.
- **Two dates for one title within a document is a conflict; three or more is a series.** Both items are kept and flagged `conflictingDate`; the weaker one is `.needsReview`. This is the in-document version of the spec's "emit both, flag the conflict".
- **Policies are checked for exact wording.** A model quote that is not a substring of the document is rebuilt from the document's closest sentences; if that fails the policy is kept with `verbatim: false`.
- **Eval pass/fail is recall ≥ 0.9 and zero spurious `.ready` items.** Spurious items that land in the review queue cost a tap and are reported (`falsePositiveRate`) but do not fail the suite.
- **No concrete examples in the schema descriptions.** The 3B model copied the example date from `dateAsWritten`'s description ("e.g. Wed 9/9") into a Spring syllabus as the midterm date. Descriptions now say what a field is, never show a sample value.
- **Platform attribution is document-first.** Order: a platform keyword in the sentence or table row that names the item (WebAssign, Gradescope, MyLab/Mastering/Pearson, Brightspace/Canvas/Blackboard/Moodle), then the keyword on the item's grade-breakdown row, then the model's guess. The grading table is the authority on where a component is submitted.
- **Grade-table rows are recovered deterministically when the model skips them.** Lines shaped like "Name …… 20%" whose weights sum to 90–110% are read straight from the document (penalty and extra-credit lines excluded) and merged into the model's components. Weights the model leaves empty are recovered from the row that names the component.
- **A single corroborated date beats a model/wording disagreement.** When the copied wording names exactly one date and the document contains it, that date is used at full confidence and `dateDisagreement` stays as information only. A wording naming several dates still goes to review when the model disagrees with all of them.
- **TBD plus a date range stays TBD.** "TBA (December 16–22)" is `.awaitingDate`; "Friday, December 18, room TBA" is dated.
- **Output reserve is 40% of the context.** Dense schedules cost ~80 output tokens per item; with 30% the first fixture overflowed and lost a call. Chunks are now ~750 tokens on-device; more calls, no overflows.
- **Chunks are sized by date density, not just length.** Every date in a chunk is probably an obligation costing ~90 output tokens, so the extractor splits a chunk when its token count plus the fixed overhead plus the expected output would exceed the context. Dense schedule tables become several small calls; prose stays in large ones. This replaced a failed-call-then-split loop that cost 20–40 s per overflow.
- **A date printed before the item on a row with a later date is never shipped as ready.** Rows like "Sep 9 · Lab 1 · Sep 16" (session then report deadline), "HW 1 · Sep 4 · Sep 18" (released then due), and "Week 14 (May 4, 6): … presentations" (meeting dates) mark the item `dateAmbiguous` → review. Table rows are read cell by cell (runs of spaces), because the data detector reads "HW 1   Sep 4" as "1 Sep". Screenshot rows cannot use this: Vision returns cells as separate lines, so the model's Due-column reading stands there.
- **Screenshots inherit the page's only platform.** A Gradescope or Brightspace page names its platform once in the header; for image inputs that beats the model's guess. Text syllabi do not get this fallback, so in-class items keep `.syllabusOnly`.
- **"due" in the copied wording is authoritative.** Wording that names several dates lets the model choose among them only when none is marked "due"; with "due", the date after it wins and a different model pick is a disagreement → review. Empty wording is not TBD: the model's date is used but capped to review, as is any item from an image Vision could not read.
- **Row checks decide what may ship as ready.** An item is `dateAmbiguous` → review when its own row (or, for an invented title, the line naming its head word and date) puts the chosen date first with a later date after it, names dates but not the chosen one, or is a "Week N" topic line without "due"; and for a screenshot item whose row OCR could not reassemble when the page has a Released/Opens column. Vision observations are regrouped into rows by vertical position so screenshot and scan tables get the same row checks and grade-table recovery as PDF text. `sourcePage` now survives image pages in between text pages.
- **The eval gate counts wrong-dated ready items too.** `readyErrors` = spurious or wrong-dated obligations with `status == .ready`; must be zero. Grade-table recovery reads only a contiguous run of percentage rows, so a letter-grade scale elsewhere cannot spoil it.

## 2026-09-04 · M2 setup

- **Identifiers.** Bundle ID `com.daniel.horizon` (the user's choice for provisioning); share extension `com.daniel.horizon.share`; App Group `group.com.daniel.horizon`; CloudKit container `iCloud.com.daniel.horizon`; URL scheme `horizon://`. They live in exactly two places that must agree: `project.yml` (bundle IDs, entitlements, BG task id) and `HorizonCore/Identifiers.swift` (what the code looks up). The generated `.xcodeproj` and the entitlements files are outputs of `xcodegen generate`; edits made there are overwritten.
- **Manual entry exists, as a fallback.** The user asked for an editor for obligations that never arrive as a document. SPEC §2.1 stands as the product's identity: no composer on any primary path. The review queue's editor doubles as the manual editor, reachable from an overflow menu ("Add by hand…"); such items carry `origin = manual` so provenance still answers "where did this come from".
- **Xcode project is generated by xcodegen from `project.yml`** (installed via Homebrew). The `.xcodeproj` is git-ignored and regenerated with `xcodegen generate`; agents edit YAML, not pbxproj.
- **Signing: free Personal Team only.** No provisioning profiles, no paid program, so CloudKit is unavailable. The store runs in the App Group with `cloudKitDatabase: .none` unless the `HORIZON_CLOUDKIT` compile flag is set; the schema already obeys every CloudKit constraint (all fields optional or defaulted, no unique attributes, optional relationships with inverses) so enabling it later is a flag, not a migration. Simulator and local macOS builds do not validate entitlements. `DEVELOPMENT_TEAM` is read from a git-ignored `Config/Local.xcconfig`.
- **Source files are stored on disk, not in the model.** CloudKit mirroring syncs every attribute of a synced model, so the "external storage but do not sync" idea from SPEC §4.4 cannot be expressed. Documents are written to the App Group container under `Documents/<sha256>.<ext>`; `SourceDocument` records only metadata. "Available on this device" = the file exists.
- **Share extension enqueues; the app parses.** The extension copies the document into the App Group inbox, records a queued `SourceDocument`, and the app drains the inbox on launch, on foreground, and from a `BGProcessingTask`. If the on-device model proves usable inside the extension, the extension will parse in place and the inbox becomes the fallback.
- **`fm` CLI license is accepted** on this Mac; the code does not use it.
- **For text documents the model's platform guess is not evidence.** The on-device model defaults to "lms" and labels grading rows it cannot read as WebAssign. Platform now comes from the item's own row, else its grading row, else `.syllabusOnly`; only screenshots fall back to the model's reading of the picture. Likewise the grading row's own percentage beats the model's figure for a component weight (the simulator's model returned 10% for a row that says 15%).
- **A model date counts against an item only when it sits on the item's own row.** The simulator's model shifted every date by a week; each shifted date coincided with a neighbouring row and sent eight correct items to review. The row check keeps the real ambiguity case (session date vs. report date on one row) and drops the coincidences.
- **Simulator findings (iPhone 17 Pro Max, iOS 27).** FoundationModels works in the simulator on this Mac and takes ~90 s for the sample syllabus; its output is markedly worse than the macOS run of the same model (wrong years, shifted days, "lms" everywhere), which is why every deterministic guard matters. `OCRTool` does not exist in the simulator SDK, so image pages there rely on the model alone plus Vision text. An iOS app bundle must not contain a top-level folder named `Resources` (the installer rejects it as "Missing bundle ID"); bundled samples live in `Apps/Horizon/Samples` and are copied flat.
- **The simulator runs a 300M-parameter model** (`com.apple.fm.language.instruct_300m` per modelmanagerd), not the device/Mac 3B model. Simulator output is therefore only a smoke test of the pipeline and the guards; extraction quality is measured on the Mac (evals) and, later, on a device. A freshly erased simulator reports the model "not ready" for a minute or two after boot; documents now stay queued through that instead of being routed to Private Cloud Compute.
- **No forced dark mode.** SPEC §9 says "dark by default"; the user asked that the app respect the system appearance instead. All colors are semantic (`.primary`, `.secondary`, system backgrounds) plus the one accent, so both schemes read the same way.

## 2026-09-04 · M2 review fixes (SPEC §4.4 hardening)

- **Absence means deletion only for reminders this device has seen.** Each device keeps a local, unsynced set of external IDs it has observed in EventKit (`SeenReminderIDs`, in the App Group's UserDefaults). A reminder missing from that set is one that has not arrived yet, not one the user deleted. A missing Horizon list (never created, iCloud signed out, or deleted wholesale) reconciles nothing and recreates nothing; the app keeps its rows and says so in the log.
- **Only the device that created a row creates its reminder.** `Obligation.createdOn` names it; other devices wait for the reminder to arrive through iCloud (or for the synced external ID) and repair by deep link. This closes the two-device duplicate window that "create when the ID is nil" left open.
- **Deletion in Reminders is honoured in any state,** not only `.projected`: a reminder deleted while its item sits in review is tombstoned on the next sync. Discarding an item in the app removes the reminder Horizon created; reminders the user made themselves (`origin == .reminders`) are never removed.
- **Re-ingest matching runs in passes over a consumed pool:** same title and day, then same title with one side undated, then a similar title on the same day, then the one same-titled row whose date moved. Course-less documents (screenshots) match against course-less rows, so a second crop of the same list is not a second set. Courses with different codes never merge on title alone.
- **A hand edit that disagrees with a reissued document is shown, not swallowed:** the overridden field stays, `changeNote` reads "Document now says …; your edit was kept", and the item does not go back to review.
- **Notes go both ways.** Horizon's generated lines and the user's own text coexist in a reminder's notes; text typed in Reminders is preserved on update and imported as an override, and notes edited in the app reach the reminder. `projectedNotes` records what was last written so a Reminders-side edit can be told from an app-side one.
- **Schema V1 is still mutable.** `createdOn` and `projectedNotes` were added to V1 because nothing has shipped; the append-only rule starts with the first release.
- **Deferred, tracked:** an in-app detail view for the reminder's provenance link (the link currently opens the item in the editor); a Retry that is smarter than "queue again"; EventKit implementation tests (need an Xcode test host with a Reminders store).
- **Ingest streams into the UI.** `IngestOptions.progress` receives `IngestEvent`s from the extractor (`streamResponse` + `PartiallyGenerated`) through the ingestor and coordinator; the app shows a "Reading …" section that fills in item by item, plainly for now. Streamed rows are the model's raw words; statuses and resolved dates appear only after the merge. The user asked for visible progress on anything this slow.
- **Documents also come from the photo library and the camera.** `ImportMenu` offers Files, Photo Library (PhotosPicker, up to 10 images) and, on iPhone/iPad, VisionKit's document scanner, whose pages become one image-only PDF. The share extension, the URL scheme and the macOS watched folder remain the other entry points.

## 2026-09-04 · M3 Coverage

- **Coverage is the home screen.** M2's "Next up" list is gone from the root (the strip in M4 is its real home; each course's detail still lists its obligations). Above the course stories sit only the live reading section and a one-line link to the review queue, written as a sentence, never a count badge.
- **Suspicion score** = 0.05 per day silent (capped at 30 days, 1.0 when nothing was ever ingested) + 0.4 per cadence gap + 0.3 per platform the syllabus names that no document has come from + 0.3 when a course with a grade table has nothing due in the next 14 days. It only orders the list; the number itself is never shown.
- **Cadence gaps compare rhythm to the next 14 days**, not the whole term: weekly implies 2 items in the window, biweekly 1; a stated count with fewer than half on file is also a gap. The sentence is the product ("its syllabus implies weekly quizzes; none on file for the next two weeks").
- **"Never ingested" means no document came from that platform.** Screenshots record the platform their page names (`SourceDocument.platform`); syllabi record none. A course whose syllabus puts homework on WebAssign stays flagged until a WebAssign screenshot has been read.
- **Story typography:** New York (serif) title 2 for the sentence, SF large title with tabular digits for the two figures, small uppercase captions, secondary subheadlines for further gaps. Accent only on "days silent" from 7 days up.

## 2026-09-05 · Real syllabus: the "loops back to 0" bug

- **Output is capped and salvaged, never retried.** The user's five-page syllabus overflowed the on-device context on its first chunk: two pages of policies made the model quote far more than the output reserve, and the size estimate only counted dates. Each overflow halved the chunk and retried (a minute per attempt), restarting the live list, which read as a loop. Now `maximumResponseTokens` is the reserve, and when the model runs out (or overflows anyway) the complete items from the last streamed snapshot are kept and the chunk is done; splitting remains only for a chunk whose input alone does not fit. Policies are limited to one sentence each and six per chunk.
- **Long documents are long.** Ten chunks at 20–90 s each is 5–15 minutes on-device; the live section now shows "part N of M", and the next lever is the Private Cloud Compute route for documents over a few pages (one pass, 32k context), which the store already models (`awaitingCloudParse`).

- **A title the document never prints is not the item's title.** The 3B model copied "HW 3" and "Midterm 1" from the prompt's own examples (as it had copied example dates from the schema before), so the prompt now names no example titles, and the merger checks every title against the document text. A missing title is replaced by the label of the line that carries the item's date ("Exam 1" for the model's "Midterm 1"); a label cut from prose ("Opt out of the program") or no label at all sends the item to review (`titleFromLine`, `titleNotInSource`).
- **A grade table that totals 100% is complete.** Components the model named that are not rows of it are dropped (the model's "Homework" was the "WebAssign 4%" row under another name, and a 0% weight it emitted is treated as no figure), so weights and points come from the table alone.
- **Term dates are the document's, not the model's.** The model put fixture 15's term start on September 7 when the syllabus says classes begin September 2, which shifted every week-relative deadline by a week (and past the eval gate only because those items landed in review). The merger now reads "classes begin … and end …" / "first (last) day of class" sentences itself; a model term date is kept only when the document names that day, and an image page keeps the model's reading.


## 2026-09-05 · M3 review fixes

- **A cut-off stream loses one element, not one per list.** Salvage now drops only the last element of the list the model was writing when output ran out (lists arrive in schema order); a chunk that overran while quoting policies keeps every complete obligation.
- **Streamed rows are numbered per model call**, not per chunk index, so a split chunk or an image page after text pages no longer reuses ids (SwiftUI showed duplicate rows); image pages continue the "part N of M" count after the text chunks. A partial snapshot is forwarded only when an item appears or its date arrives.
- **A read that fails still ends in the UI.** The ingestor emits `finished` on every exit, and the app clears the live section after a drain. Cancellation (background time expiring) is rethrown instead of being logged as a chunk failure, and the coordinator leaves that document queued rather than marking it parsed with half its chunks.
- **Only adjacent repeated lines collapse.** The earlier rule removed any line that had appeared before on the page, which deletes a weekly "Reading response" row; the real syllabus's duplicates are adjacent. The in-line phrase rule needs words, not a run of "10%" cells.
- **A row label is taken only from the item's own line**: one that shares a word with the model's title, or the sole line naming the date; the label is cut at that date (so a dated week preamble is skipped), never at the first date on the line, and a label that is another item's title is refused. Wrapped grade rows ("Homework (WebAssign, lowest two" / "dropped) … 15%") are joined before the table is read, and among several 100% tables the one naming the model's components wins over the longest (a rubric).
- **Coverage's window is calendar days**: through the end of the 14th day from today, so a date-only deadline that day counts; rhythm is expected only for the days of the window inside the term (none before the term starts, one week's worth in the last week).
- **Imports clean up and speak up.** Photo and scan temp files are removed once the app has its copy; unreadable photos and a failed scan set the error line; the scanner's PDF is drawn off the main thread.
- **The deep link's sheet stays open**: the handler ignored the nil reset it caused itself.
- **More words the model copies from the prompt.** With no example titles left to copy, the 3B model started copying whole rows and section headers as titles ("Lab 1 Data and R basics", "MyLab Homework" for every homework) and listed the prompt's item types as grade components. The title rule now says "short name only: the label of its own row or line without its date, topic, or description"; the merger keeps only the item's own cell when a title spans a row's cells, and treats a title that is a grade-table row name like an unprinted one (the row label wins). A `dateAsWritten` of "null" or "none" is no wording, so the model's date for it goes to review.
- **The course's meetings list is capped at seven.** Fixture 02's first page overran the output budget with nothing but a course header and four components streamed: the model looped on `meetings`. Guided generation enforces `maximumCount`, so the loop cannot eat the budget.
- **Known limitation: a chunk can still overrun with nothing to salvage.** Fixture 02's header-and-policies half chunk hits the output cap after streaming only the course and four components (the raw JSON tail shows the object closed early; the model then runs on). Obligations from that page live in the schedule chunks and are unaffected; only that page's policies are lost, and the verbose log now prints what streamed before the cut for the next look.
- **Example titles are back in the prompt, now that a copied one cannot ship.** Without them the model copied whole schedule rows as titles ("Week 3: Trig substitution. HW 3"), which also lost the homework's component and platform. The title-in-source guard catches an example copied for an item the document never names, and `Merger.ownName` cuts a row-shaped title down to the item's own name (the component word next to its number, with an acronym before it: "MP HW 6", "Lab 6 report", "Lab 1"); names of three words or fewer are never touched.

## 2026-09-05 · Private Cloud Compute option

- **Reading in Private Cloud Compute is a user setting**, off by default: the More menu's "Read in Private Cloud Compute" toggle sets the ingest route for the next drain (`IngestCoordinator.setRoute`). The user asked for it because on-device parsing of a long syllabus is slow and heats an iPhone 16 Pro Max. With the setting on, a cloud refusal leaves the document "Waiting for Private Cloud Compute" (with the reason) instead of failing it; turning the setting off reads it on device.
- **Touching `PrivateCloudComputeLanguageModel` without the entitlement traps the process** (a fatal error, not a thrown error, on iOS), so the app reads its own code signature for the entitlement first, from the executable's embedded entitlements plist, and only then asks the model whether it is available.
- **PCC needs Apple's managed entitlement** (`com.apple.developer.private-cloud-compute`, requested through the developer account). Without it every request fails with an opaque error (-1 from the CLI; a fatal "Missing entitlement" in a script), even though `availability` reports available, so the app also checks its own signature for the entitlement and shows why the toggle is disabled. The entitlement file is opt-in: `Horizon-PCC.entitlements` is selected from the git-ignored Local.xcconfig once the team has been granted it. The eval suite has therefore never run on the cloud route.

## 2026-09-05 · Reading progress and cancel

- **The live section is a progress bar, not a list.** The user asked that the home page not fill with streamed rows by default: the section shows the document name, "part N of M · K found so far", a determinate bar (parts finished plus how far the current part has streamed) and two controls, a disclosure that reveals the streamed rows (closed by default, remembered) and Cancel.

## 2026-09-05 · M4 Horizon strip

- **The strip is a Canvas, not a chart or a calendar.** One horizontal band per course over one time axis; each mark's height is `Strip.mass` (square root of points at stake over 35, so a 4% set is a hairline and a 30% final fills the band), review items are outlines, completed ones fade. Pileups (two or more items of at least 10 points within 24 hours, `Strip.collisions`) draw an accent hairline across every band with the day named above it, and their marks take the accent; the accent is used for nothing else here.
- **Interaction:** a tap or a press-and-drag scrubs a day into the header (a plain drag pans, so scrolling and scrubbing do not fight); pinch zooms between the whole semester and two weeks across the width, with a Zoom menu for the same three stops. Course codes are pinned to the leading edge so they stay while the strip scrolls.
- **Screens are tabs now** (Coverage, Horizon; Now in M5). The moment a document resolves is the one animation: marks that arrive while the strip is on screen grow in over 0.6 s; what is already on file simply is.
- **Not done:** the strip does not open an item's editor yet (the header lists the day's items; the course page and review queue edit them), and a term with no dated items shows an empty axis around today.
- **Lecture topics, readings and class sessions are not obligations, whatever the model says.** The Organizational Behavior syllabus' week-by-week schedule produced "Chapter 2, Diversity…" and "SHARK TANK GROUP WORK SESSION #1" as ready items. A title that names no deliverable and starts with chapter/lecture/topic/reading/read/review, or that names a session (work session, planning time, exam preparation, no class, reading day, finals week), is skipped and counted in the warnings.
- **The date must sit on the item's own line.** "MyLab work" shipped with the opt-out deadline from another paragraph because both the words and the date were somewhere in the document. When the wording is an explicit calendar date, the merger now checks that a line naming the item (or its wrapped date line) names that date; otherwise the item goes to review as `dateNotOnRow`. A table whose cells wrap one per line (the Financial Accounting deadlines table) lands in review for the same reason, which is the honest outcome.
- **Same-day titles nested in each other are one item** ("Election 2026 assignment" and "ELECTION 2026: POWER & POLITICS IN ACTION — DUE"); the grade table's figure overrides a model weight that disagrees ("Problem sets (written) 10%" against the table's 4%); a week number printed before a month ("17 Dec 21-25") is not the 17th.

## 2026-09-05 · Managing items, editing courses, course names

- **Any item can be edited or deleted**, not only those in review: a row on the course page opens the editor (a sheet; Cancel leads, Save trails and is disabled until something changed; swiping the sheet away with unsaved changes asks first), and a trailing swipe deletes. The editor also carries a Delete button behind a confirmation dialog, since from there the intent is less certain than a deliberate swipe. Deleting soft-deletes the row and removes its reminder on the next sync. Edits set the same user overrides the review editor sets.
- **Courses are editable after parsing** (name, code, term, term dates, instructor) from the course page's Edit button; each edited field becomes a course override that a reissued document leaves alone (`Course.userOverrides`, a V1 addition).
- **The app names courses by their name, not their code.** Coverage sentences, the strip's bands and header, rows, pickers and reminder titles ("Quiz 3 · Calculus II") all use `displayName` (the title, falling back to the code); the code becomes the small kicker above a Coverage story. The user asked for it; codes are for registrars.
- **HIG checks applied:** swipe actions on list rows (iOS), no alert for the common swipe delete, a confirmation dialog with the destructive action first for the editor's Delete, sheets with Cancel/Save in the standard placements and inline titles, labelled text fields with example placeholders, compact date pickers, verb-first button labels in sentence style, 44 pt controls, VoiceOver labels on icon-only buttons. Debug launch flags (`--open-course`, `--open-item`, `--open-course-editor`) open each screen for screenshots.

## 2026-10-13 · App Intents, one per verb

The owner: too many separate intents, and too many tools confuse small models. Follow Apple's own apps; a variant (Read a Document beside Read on This Device Instead) is a parameter of one action, the model a setting. Researched in Apple's documentation, HIG and WWDC22–26, and in the App Intents metadata that macOS 27's and iOS 27's own apps ship with (`Metadata.appintents/extract.actionsdata`).

- **What Apple does.** Each intent does one thing, and a variation is a parameter ("Open Shelf" with an enum, not one intent per shelf). Its apps keep one action per verb and kind of thing (Notes: Create Note, Create Folder; Delete Notes, Delete Folders; Open Note, Open Folder…), and fold the rest into parameters: opposites share one action with an operation (Pin or Unpin Notes, Add or Remove Note Lock); every setting is one action, the setting a parameter (Change Notes Setting, Change Book Appearance); every place is one Open with an enum (Open Notes View, Open View in Books App); an update is one action with optional fields (Mail's Update Message: read, flagged, junk, mailbox). They ship one to three App Shortcuts.
- **What Siri's model sees** (WWDC26's sessions and lab): only schema intents, plus App Shortcut phrases. Horizon's custom intents were never among its tools, so the count mattered for Shortcuts, Spotlight and Shortcuts' Use Model action, not for Siri; what Siri reaches depends on the schemas and the indexed entities. A schema intent may take optional parameters of its own (the build accepts them), but Siri ignores them: they are for Shortcuts.
- **38 discoverable intents became 23, ten App Shortcuts seven.**
  - Get Items (was What's Due, What Matters Most Next, Items to Review, Find Pileups): Show (Due, Most Important, Piling Up, Waiting for Review, Done), When (the stretches, Overdue, Any Time; by default this week, for what matters most the next two weeks, for pileups and review any time), Course. Most Important lists the heaviest first (`DueQuery.byWeight`), its first `nextByWeight`'s.
  - Get Course Info (was Get a Course Policy, Get Course Details): Topic (Grading, or one of five policies), About (any words, say "calculators"), and with neither, the course itself: who teaches it, the term, the room, its grade table, the policies it states (`CourseQuestion` reads the words).
  - Read Document (was Read a Document, Choose a Document to Read, Retry Reading, Read on This Device Instead, File Document Under Course): Files; or a Document already in Horizon, read again, or filed under the Course; On This Device; with nothing given, Horizon opens at Choose From (Files, Photos, Screenshots, Camera).
  - Change Settings (was Choose Where Documents Are Read, Plan the Day with Claude): Read Documents With and Plan the Day With (Claude or This Device), and the Claude model, which no intent offered before. This is the owner's "inference provider" setting. Turning Claude on asks, says what is sent, and wants the device unlocked.
  - Plan My Day takes Until (was Plan Tonight Until) and Keep in Mind (was Tell the Planner). Sync with Reminders takes Recreate the List (was Recreate the Horizon List). Open Page, an `OpenIntent` on the page enum, takes Horizon's Course and Day (was Show on Horizon).
  - Add Item takes Every (a weekday), Until (an item) and First Number (was Add Weekly Items); Change Item takes Review (Confirm as Read, Use the Other Date; was Confirm Item). Both are schema intents, so these are Shortcuts' alone; Siri gives a repeat as the schema's own and needs no phrase.
  - What's on My Plan is Get Today's Plan (a verb and a noun, as Apple titles actions).
- **Decided for the owner:**
  - On This Device is a switch, not a choice of model per read. A per-read Claude would send a document the user's own switch says to keep, and Settings stays the one way to Claude.
  - Each kind of thing keeps its own Open (course, document, policy; items through `.system.open`). Spotlight opens a tapped result through its type's `OpenIntent`, cannot see one that is not discoverable, and two may not share a type.
  - Delete Course and Delete Document stay apart, as Apple's apps keep one delete per kind. iOS 27's union parameters could make them one, for no gain but a line in a list.
  - App Shortcuts: What's Due (Show's values make "What's most important in Horizon" and "What's piling up in Horizon" shortcuts of their own), Plan My Day (tonight's end), Today's Plan, Course Info, Check Coverage, Read a Document, Open Course. Add Weekly Items went: Siri's own add takes a repeat with no phrase.

## 2026-10-13 · An item's grade row and site, by Siri and in Shortcuts

The owner asked Siri to change what items count toward and their platform, several at once. Siri said it could not. Then the gap was traced, and filled.

- **Why Siri said no.** Siri changes an item only through the reminders schema's Update Reminder (Xcode 27's schema database). Its fields are the name, notes, tags, links, due date, repeat, done, flag, list and location. It has no section field (Create Reminder has one), and nothing like a site. The extra parameters an app adds are invisible to Siri. Update Reminder does run once per item when it is given several, so a change Siri can say applies to many items in one sentence.
- **The grade row and the site ride on the item's tags** (`ItemTags`). An item's tags are its grade row and its site, so Siri reads both there. A tag Siri sets that names a site (WebAssign, Gradescope, MyLab or Pearson, Canvas and the other LMSs, or "none") sets the site. One that names a row of the course's grade table sets the row. Any other tag is said to be neither, and left off. "In Horizon, tag all of Calc's homework WebAssign" should now work. A sentence about "platform" or "counts toward" may still not, since Siri has no such field to map it to. That is for the owner's voice to tell.
- **Shortcuts showed only the schema's fields.** "Update Reminder" in the simulator's Shortcuts listed the schema's fields alone. Change Item's Review, and Add Item's Every, Until and First Number (DECISIONS 2026-10-13, earlier), never appeared. Only AppIntentsTesting reached them. Each schema intent now gives Shortcuts its own summary with them in it. Change Item gains Counts Toward (a row by name, read against the item's course) and Site; Add Item gains Site.
- **Horizon's words in Shortcuts.** The schema intents are titled Add Item, Change Item, Delete Items and Add Course (they read Create Reminder, Update Reminder, Delete Reminders and Create List). Their fields say Item, Course, Done and Counts Toward. The generated Find actions ("Find Reminder", "Find List", "Find Note") and an entity's type name in a picker keep the schema's words: the build ignores an override of a schema entity's type name.
- **Verified.** 181 IngestKit and 135 HorizonCore tests. AppIntentsTesting sets a row and a site through Change Item's own parameters, and a site through a tag as Siri does. The simulator's Shortcuts shows the new titles and Change Item's new fields. Not verified: Siri by voice, and whether Shortcuts runs Change Item once per item when handed a list. Repeat with Each does it either way.

## 2026-10-22 · The 5.5 models

- **Sonnet 5.5, Opus 5.5 and Haiku 5.5 replace Sonnet 5, Opus 5 and Haiku 4.5.** Sonnet 5.5 stays the default. The cases are named by line now (`.sonnet`, `.opus`, `.haiku`; `horizon-parse --model sonnet`), so the next bump changes ids, not names.
- **Thinking off is sent per model.** Reading still asks for no thinking:
  - Sonnet 5.5 rejects `thinking: disabled` with a 400. It gets `between_tools` instead, which means no thinking because reading uses no tools.
  - Haiku 5.5 now thinks by default and takes effort. It gets `disabled`, and its effort is sent.
  - Opus 5.5 cannot be kept from thinking at any effort. A request that asks for none is sent at low effort instead. That reading spends some of its output budget thinking, which is the failure the no-thinking rule was made for (DECISIONS 2026-09-14). No eval has measured it on Opus 5.5 yet.
- **Decided for the owner:**
  - A choice stored as an older id is taken as its line's current model (`ClaudeModelChoice(stored:)`), so someone who chose Opus 5 keeps Opus.
  - Change Settings' Claude Model cases were renamed from `sonnet5`, `opus5`, `haiku45` to `sonnet`, `opus`, `haiku`. A shortcut saved with the old value has to be set again, once.
  - The server-side refusal fallback (`fallbacks: "default"`) is not sent. It would let Anthropic answer with a model the user did not choose. A refusal still ends the part as before.
